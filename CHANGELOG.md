# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project
adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Entrances, instead of things appearing.** Three places used to pop: a disclosure body snapped open
  and shoved every section below it, a concept strip replaced itself between two frames when the batch
  was rerolled, and the readability notice blinked in and out as the backdrop changed.

  A disclosure now grows its body over `--duration-base`, clipped only while the height is moving — left
  clipped afterwards it would cut the focus ring of the last row, so the clipping is released when the
  animation completes. A rerolled strip arrives as a batch: each tile fades and rises eight units, thirty
  milliseconds apart, capped at the fifth so a long batch does not keep its last tile waiting. The notice
  fades in with a six-unit rise and leaves the same way.

  All three follow the rule the panels already set: **a fade may stay when motion is reduced, a move may
  not**. The offsets and the stagger drop out under `prefers-reduced-motion`, the fades do not, and the
  disclosure skips its animation entirely rather than running it at zero duration — a height animation
  has to resolve `auto` into pixels, and not starting it is the only way to be sure it cannot resolve to
  nothing.

  The strip's animation sits on a wrapper around each tile rather than on the tile, because the tile's
  opacity is state — dimmed when unselected, full on hover — and an animated inline opacity would
  overwrite it.

- **An `apparatus` engine, for marks that should look made rather than drawn.** The vocabulary is
  equipment: a core with its corners cut, arcs that stop short of closing, radial ticks with one long
  index, brackets that frame without enclosing. What carries it is the contrast between a single solid
  mass and everything else — a 4.6-unit hairline at 512 — rather than any one of those shapes.

  Four styles share the core and vary only the grammar: `dial` sets a segmented bezel over a tick band
  with the gaps under the long ticks, `reticle` runs crosshair arms through a ring, `brackets` places
  four corner marks and a base rule, `sector` puts a heavy arc over a thin ring and is the only one with
  a direction. The initials are identical across all four, and a test asserts it, because a style that
  nudged the letters would make the same name look like a different name in each.

  The style is pinnable through `preferences.style`, so rerolling explores the grammar while holding the
  one the reader liked. Routing weights it in the technical moods only — `cyber-security` 3,
  `developer-tools` and `infrastructure` 2.5, `aerospace` 2.5, `software` and `ai-ml` 2 — and at zero
  everywhere else, which leaves the existing routings untouched: the determinism manifest passes
  unchanged, and `concepts.svg` regenerated byte-identically.

  Two constraints bound the drawing rather than a preference. The chamfer bounds the type, because a
  letter's ink can reach the corner of its box and the cut is the one place that can bite into it; the
  safe half-width is 0.186 of the canvas against a letter box of 0.174. And the draw order — grammar,
  then core, then type — is what guarantees no tick or arc crosses an initial, instead of clipping one.

- **Vendor chunks in the studio build.** React and the animation library are emitted as their own chunks
  instead of one 671 kB file, so editing studio code no longer invalidates 345 kB of cache on every visit,
  and the browser can fetch the three in parallel over HTTP/2. This is a build-config change with no
  runtime effect — measured after the split: react 210.6 kB, motion 134.3 kB, app and generated brain data
  342.9 kB.

  The generation itself was measured rather than assumed: `generate()` runs on every keystroke and costs
  2.5 ms at the median and 3.8 ms at the 95th percentile for six concepts, so it is not the thing making
  typing feel slow.

- **Keyboard shortcuts in the studio.** `Cmd/Ctrl+Z` and `Cmd/Ctrl+Shift+Z` undo and redo; `1`–`9` pick a
  concept directly; `,` and `.` step between them; `-` and `=` zoom, `0` returns to fitting the window;
  `R` rerolls; `E` toggles edit mode; `Escape` closes a drawer, or clears a part selection once no drawer
  is in the way. Each is also reachable by pointer, so nothing becomes reachable only by keyboard.

  Keys pressed inside a field belong to the field. `Cmd/Ctrl+Z` in the brand-name box is undo-my-typing
  rather than undo-my-last-edit, and a digit typed into a field is a digit rather than a concept index —
  without that guard a single keystroke silently rewrites the design.

- **The studio says when a mark cannot be seen on the sheet behind it.** The dark backdrop exists so a mark
  can be previewed against a dark surface, and twenty-three of the thirty curated palettes are drawn for a
  pale one — so choosing both left dark ink on a near-black sheet, an empty-looking square with nothing to
  explain it and no way back except guessing which palette would work. The stage now measures the contrast
  between the colours the mark is actually painted in and the sheet it is actually on, and when the worst
  of them falls below 2:1 it says so in the stage's gutter below the sheet, with the measured ratio, and
  offers the palette that reads best there.

  It sits in the gutter rather than on the sheet because the first version was on the sheet, which is the
  one place it must not be: at a 242px sheet it covered 45.8% of the artwork, hiding the very thing it was
  reporting on, and the smaller the sheet the worse the share. Measured after the move: 0%.

  It offers rather than applies: the backdrop is a viewing choice and the palette is a design decision, so
  recolouring the mark because of where the reader chose to look would be a larger surprise than the one
  being fixed. Confirmed against the reported case — a `#451a03` mark at 1.23:1 on `--paper-dark`, and the
  same mark at 14.72:1 on `--paper-light`; taking the offer moves it to a palette that reads.

  The threshold is 2:1, calibrated against the case rather than borrowed from WCAG. Its 3:1 is the bar for
  text, where the cost of marginal contrast is fatigue; a mark is looked at, and its failure mode is being
  absent. The first version used 3 and cried wolf: it kept warning about a green wordmark that is plainly
  legible at 2.8:1, which would have taught the reader to ignore a notice about invisibility.

  The sheet's colour is read from its own resolved custom property rather than copied into JavaScript, so
  the measurement cannot drift from what is painted; the `oklch()` conversion that requires is guarded by
  a test that fails on the token sheet if a paper colour ever moves to a form the measurement cannot read.

- **Part editing in the studio.** Each concept's SVG is now rendered inline rather than as an image, so
  every top-level path is a selectable, editable part. Click a shape on the canvas — or its entry in the
  inspector — to select it, then drag to move it, or use the rotate, scale and fill controls. Parts can
  be hidden, and every gesture is undoable. Edits are keyed by the concept's seed fingerprint, so they
  follow the mark across regenerations, and an unedited concept still exports byte-identically to the
  generator.

  The stage used to render the mark as a data URL in an `<img>`, which is the right way to show a finished
  document and the wrong way to edit one — an image has no parts. Rendering the paths inline is what makes
  each shape selectable, and it costs nothing: the document is a handful of paths either way. The generator
  forbids script and event handlers in its output, so putting that markup in the DOM is safe by construction
  rather than by sanitising it on the way in.

  A "part" is a top-level `<path>`, which is the granularity the generator's flat output gives. For an
  abstract mark that is every shape in the composition; for a wordmark it is the pictogram and the word as
  a whole, because the word is compiled into a single path by the glyph compiler — splitting it back into
  letters would mean re-parsing the outline, which the project forbids at runtime.

- **`author` in the manifest**, and the release link in the changelog footer pointed at
  `github.com/sigilgen/sigilgen` — a placeholder that has never existed — rather than this repository.
- **A guard on the build's version substitution.** See "Fixed" below.
- **`LogoConfig.preferences`.** Holds a design decision still across every concept while the rest keep
  varying: `container`, `layout`, `treatment`, `accent`, `frame`, `mode`. Every dimension is optional,
  an absent one behaves exactly as before, and a value the engine does not offer is ignored rather
  than rejected — a preference is a hint about taste, and a hint must not be able to fail a render.
- **Exported engine candidate lists.** `FRAMES`, `MODES`, `ACCENTS`, `LAYOUTS` and `TREATMENTS` join
  `CONTAINERS` and `LETTER_LAYOUTS` as module exports, so a consumer can offer the same choices the
  engines accept instead of keeping a second copy that will drift.

### Removed

- **The design notes panel.** The inspector ended with the generator's own notes as a numbered list —
  nine lines on a typical concept, in English, in a panel that had already stated the engine, the
  typeface, the pictogram and the palette three rows above it. Three of the nine were resolver
  diagnostics: the palette pool, the typeface pool, the runner-up mood. Those belong in a log, and they
  made the one screen in the studio that read like one.

  The panel now carries the decisions and the export and nothing else: six rows, each a value the reader
  can act on. The palette gained a row of its own on the way past, because a run draws a different
  palette for every concept, so the left panel's selection says nothing about the concept on screen.

  `conceptNotes` is untouched. It still travels through the API and the CLI's JSON output, and the tests
  that assert on a decision still read it.

### Fixed

- **Five letters were drawn wrong in every family.** A wordmark containing any of them showed it, and the
  cause in each case was the same: a stroke placed where it looked right rather than against the thing it
  has to join.

  `J`'s hook was a half-ellipse centred _on the stem_, so its two ends landed half a glyph apart either
  side of the letter and the stem came down between them over nothing — the hook hung below the stem as a
  detached smile. It is centred so its right end wraps the stem's outer edge, and the joint is continuous
  in both terminal styles.

  `G`'s arc stopped at the horizontal while its crossbar's spine stood at the far right, and the
  crossbar's corner looked like a tab glued on. The arc now runs down to the angle where its outer edge
  meets the spine — computed from the stroke and the glyph width rather than a constant.

  `K`'s arms began a third of a glyph to the right of the stem, so the letter was a vertical bar with a
  floating chevron beside it. `R`'s leg began mid-glyph, with the same wedge of background under the bowl.
  Both now spring from the stem. `Y`'s stem stopped exactly on the crotch, leaving a wedge of background
  between the two diagonals above it; it runs up into the join now.

  `N`, `W`, `A` and `B` are still imperfect, and what is left there is a different kind of work. Their
  gaps are at corners and interior peaks, where the fix is a filled wedge — the way `apexWedge` already
  fills the point of a `V`. Extending the stroke instead was tried on `N` and is wrong: a stroke's end cut
  is perpendicular to it, so lengthening it pushes a spur out past the baseline.

  None of this was a winding or a path-union problem. Every contour of every glyph was measured, and they
  all wind the same way, so the non-zero merge already works; a union would have changed none of the five.

- **The drawers animated anyway when the system asked for less motion.** `tokens.css` zeroes every CSS
  transition and animation under `prefers-reduced-motion: reduce`, and its own comment says as much —
  "rather than animating regardless". It covered everything except the two panels, which animate through
  framer-motion: that library writes an inline style and animates it itself, so it never sees a CSS rule.
  The panels kept resizing the stage over 280ms, which is the one motion the setting is really about,
  because it does not fade in place — it reflows everything beside it.

  The panels now watch the query themselves through a `useReducedMotion` hook and take their transition
  from `panelTransition`, which returns a duration of 0 when it matches. The scrim and the mark's
  cross-fade deliberately keep their timings: both are opacity only, and a fade in place is not travel.

  Three guards, each confirmed failing against the code before the fix: the reduced branch returns 0
  rather than 0.28, both drawers are checked to ask for it instead of a literal, and the hook and the
  stylesheet are checked to be watching the same media query — because if those two ever drift apart the
  CSS half keeps reducing while the JS half silently does not.

- **Controls that were harder to hit than the controls beside them.** The studio had four control heights
  and no reason for any of them: `Button`'s small tier was 28px, a segmented control came to 31px — and to
  a _different_ 31px in each locale, because a Han caption line and a Latin one are not the same height —
  while the text inputs and the disclosure rows were 32px. The zoom buttons and the reroll button shared a
  row with a segmented control and disagreed with it by three pixels.

  There is one number now, `--control-h`, and everything a pointer or a finger lands on sits on it. The
  worst of them was the slider: **16px tall with a 12px thumb** over a 238px track, which a mouse could drag
  and a thumb could not. The box is the hit area, so it takes the control height; the track stays 4px in the
  middle of it and the thumb grows to 16px. The switch keeps its 20px track — that is what a switch looks
  like — and puts the floor on the label, which is what is actually being hit. The panel handle, the only
  control that opens a drawer, was a **16px-wide** target and is now 24px, which is WCAG 2.2's minimum.

  Measured after: of 68 interactive elements, the only ones under 32px on their short side are two
  icon-only zoom buttons at 30×32, the two panel handles at 24×44, and the 1×1 checkbox that a `Toggle`'s
  label wraps. `tests/targets.test.tsx` holds the floor and checks the controls still reach for it.

- **Text the design system had quietly made unreadable.** Two token values failed AA, and neither was
  visible by inspection, because in each case the pairing that matched looked fine.

  `--ink-faint` carries field hints, section headings and inspector labels at caption size. It is never
  large text, so it never qualified for the 3:1 allowance: it measured **3.20:1** on the stage and
  3.41–3.65:1 on the app's surfaces in the light theme, and **4.09:1** on a card in the dark one. Solved
  rather than eyeballed — **0.52** in the light theme, worst ground 4.83:1, and **0.62** in the dark,
  worst ground 4.81:1.

  The sheet has always been unthemed: its paper colours are fixed, so a palette can be judged against a
  light or a dark page. The text drawn _on_ it was not. A reader can pair any theme with any backdrop, and
  over the two inks the empty state draws with — the first thing a reader ever sees — **eight of the
  twelve** theme-and-paper pairings were below AA and four were at or under 2.5:1, the worst being dark
  theme on the checkerboard at **1.45:1**. The sheet now declares which sort of paper it is, and takes its
  ink from the paper rather than from the theme. The same fault in the outline drawn around a selected
  part, where the dark theme's accent measured **1.96:1** on the checkerboard, went with it.

  It is a test now rather than a habit: `tests/tokens.test.ts` parses the stylesheet and fails if any ink
  drops below 4.5:1 on any ground it can land on, or the accent below 3:1 where it marks rather than reads.

- **The selected segment's highlight sat in the wrong place, everywhere it was used.** The moving pill
  behind the active option was sized `calc((100% - 0.25rem) / n)` and moved by `translateX(index * 100%)`,
  which assumes the segments are equal columns and flush with the container's edge. Neither is true: the
  labels have different lengths in every control — "中文" is two Han glyphs, "English" seven Latin, "Light"
  far shorter than "Checkerboard" — and the track is inset by the container's own 2px padding, twice what
  the divisor subtracted. Measured on the second segment of the language control, the highlight was 54.5px
  wide against a 61px label and 6.5px off it, drifting further the further right the selection went.

  It is now positioned from the selected button's measured box, and a `ResizeObserver` follows it through
  a window resize, a language switch, and a webfont arriving after the first paint — none of which the
  effect's own dependencies can see. Verified at dx = 0.00, dw = 0.00 against the live element, and
  visually across all three options of the backdrop control.

  A second, separate 2px offset came from the highlight having no `left` at all: an absolutely positioned
  element with `left: auto` sits at its _static_ position, which inside a padded container is the content
  box. `left-0` is what makes the measured offset mean what it says.

- **A tablet got a 116px logo preview.** The layout stopped trying to be three columns below 900px, but the
  two panels are 288 and 300 units wide and do not shrink — so at 768px both panels fitted comfortably and
  the stage was left **180px** wide, with the mark rendering at **116px**. The question a breakpoint has to
  answer is not "does the panel fit" but "is there room left for the thing the reader came to look at", and
  the old boundary only answered the first. It is now derived from the panel widths plus a minimum stage
  width rather than typed as a literal, so widening a panel moves the boundary with it instead of quietly
  reintroducing the same defect. The query is `(max-width: 1007px)`.

- **A phone painted its drawers over the mark on every load.** The store's panels defaulted to open,
  which is right for a desktop and wrong for a phone, where they are overlays. The layout effect that
  corrects them runs _after_ the browser has painted, so every load began with a flash of two drawers
  across the artwork and then animated them away. No amount of care downstream can prevent that, so the
  store now reads the viewport when it is created — the only point where the answer exists before anything
  is rendered.

- **A drawer had no scrim and no way out of it.** Overlaid panels sat on the mark with nothing to say they
  were on top, and the only way to close one was a 16px chevron at the edge of the window. Opening a
  drawer now dims the stage and tapping anywhere outside it closes the drawer.

- **The stage's sheet was not square, and the mark was not centred.** Two defects that read as one.

  The sheet is meant to be a square that fits whichever axis runs out first. It was `aspect-square
max-h-full w-full max-w-full`, and neither half of that works: `width: 100%` only ever resolves
  against the width, and `aspect-ratio` is ignored once both axes are constrained — on top of which a
  flex item's width is settled by the flex algorithm before `aspect-ratio` runs at all. Measured on a
  1440×900 window, the "square" sheet came out 1376×635, so the mark was letterboxed at fit and every
  zoom level was measured against a rectangle. The sheet is now sized `min(100cqw, 100cqh)`, which is
  `min(width, height)` of the stage's content box. Verified by measurement rather than by eye, on both
  limit axes: 1200×400 → 400×400, 300×800 → 300×300, 600×600 → 600×600, each centred to the pixel.

  The container-query units need a container to resolve against, and the stage has to be a size
  container in _both_ axes to measure its own height — `container-type: inline-size` only contains the
  inline axis, and `cqh` then silently falls back to the small viewport. The sheet came out the height
  of the window rather than the height of the stage (900 rather than 635) until the stage was declared
  `container-type: size`.

  Separately, zooming out left the mark hugging the left edge of the sheet: below fit the SVG is
  smaller than the sheet, and it was a block child of a non-flex wrapper. Measured at 75% zoom against a
  391×391 sheet: 293×293 (ratio 0.749), centred to the pixel.

- **A `scale` animation letterboxed the mark in fit mode.** The stage's cross-fade wrapper initialised at
  `scale: 0.985` and animated to `1`, which shrank the SVG's rendered box below the size its `viewBox`
  expected — so the content was letterboxed inside the sheet rather than filling it. Measured: the SVG
  element rendered at 788×634.9 (a 1.24:1 box for a 1:1 viewBox). The image this replaced never scaled;
  the cross-fade reads fine on opacity alone, so the scale is gone.
- **A hidden part was emitted rather than dropped.** `applyEdits` treated an absent edit entry as "skip
  this part", so an unedited concept exported as an empty document — the one case that must survive byte
  for byte. Only an explicit `hidden` now drops a part; an absent entry means untouched and passes through.
- **The letter `S` was not an `S`.** Every one of the eighteen families drew two C-shaped hooks that
  met at a single point — reading as a mirrored `S` with a step down its right side. The cause was not
  an angle or a winding but the construction: both bowls were ellipses `cap / 4` tall on centres
  `cap / 4` and `3 * cap / 4` from the cap line, which places the upper bowl's lowest point and the lower
  bowl's highest point at _exactly_ the same y. Two filled regions meeting on a line share no area, and
  the only place they touched at all was the single point where each ellipse sits at its extreme. No
  choice of sweep angles could produce overlap under that geometry. Each ellipse is now taller than half
  the cap, with the outer envelope still pinned to the cap line and the baseline, so the two bowls share
  real area across the waist; measured, samples falling inside _both_ bowls went from 0 to ~200 per
  family.

  The lower bowl also swept the wrong way round — `40` to `270` walks left and bottom, putting its
  terminal at the lower _right_, where an `S` has none. It is now `150` to `-100`, which is the upper
  bowl's exact half-turn, so the letter is point-symmetric and its spine crosses the waist on the
  diagonal an `S` does.

- **`sigilgen --version` reported `1.0.0` forever.** `VERSION` was a literal in `src/cli.ts` carrying a
  comment saying it was "read from the manifest at build time by tsup's `define`" — there was no
  `define` anywhere in the project. The number existed in two places, so bumping `package.json` changed
  what npm published and not what the binary printed, through every release after the first, with a
  comment that read as though the problem had been handled. tsup now substitutes `__SIGILGEN_VERSION__`
  from the manifest, which is the only copy; running from source reports `0.0.0`, because unbuilt source
  is not a release. Asserting the _wiring_ rather than the value is what makes it a guard — since the
  substitution reads the manifest at config-load time, a test comparing the two numbers would pass even
  with the `define` deleted.
- **Every small control in the studio lost its shadow in dark mode.** The segmented pill, the toggle knob
  and the slider thumb each inlined `oklch(0.22 0.01 260 / …)` — the light-mode ink. In dark mode that
  is lightness 0.22 shadowing a lightness 0.215 surface, so the shadows were not subtle, they were
  absent. They are now `--shadow-control` and `--shadow-knob`, with dark variants, which is what the
  token sheet's own claim that "components never hard-code a colour, radius or duration" was asserting
  all along.
- **Firefox slider thumbs had no ring, no shadow and no hover state.** Only `::-webkit-slider-thumb` was
  styled; `::-moz-range-thumb` got size and fill colour and nothing else, so the control looked different
  in the one browser where it looked different.
- **A colour swatch and the concept tile were unnamed sizes.** `rounded-[4px]` and `w-[4.25rem]` are now
  `--radius-swatch` and `--spacing-tile`, and the button's press depth is `--scale-press`, so all three
  are adjustable from the one place the rest of the scale lives.
- **The motion curve was written out three times.** `[0.32, 0.72, 0, 1]` appeared inline at all three
  framer-motion call sites, while every CSS transition read `--ease-apple`. Changing the curve reached the
  transitions and silently missed the animated ones. Both values now live in `lib/motion.ts`.
- **A ring erased the stroke laid across its band.** A ring is a filled outer ellipse with an inner one
  punched back out of it, so the two wind against each other on purpose — which makes the outer contour
  a hazard to anything drawn across the band. `Q`'s tail crosses it, and wound the other way the pair
  summed to zero: outer +1, tail −1, nothing left. The band went white wherever the tail passed through
  it, in all eighteen families, because every `Q` has a tail. `ring` now walks its outer ellipse the way
  strokes do; the counter only depends on the two being opposed, not on which starts ahead, so the swap
  costs nothing.
- **The apex wedge cancelled itself out of the notch it fills.** A wedge fills the background two flat
  cuts leave at a junction, and its winding is the sign of `(inner - y) * -2 * base` — so a fixed vertex
  order is right at the baseline and wrong at the cap line. Wound the wrong way it cancels against the
  arms it overlaps and takes the notch with it, which is exactly the defect it was added to repair. The
  order is read off the signed area now. Two `A`s and five `W`s had it, and only in families whose
  junction actually leaves a notch — which is why it read as a quirk of two typefaces rather than as a
  rule with a sign in it.

- **An arc band's winding must be pinned, and it must match the strokes.** `arcBandPath` documented that
  its contour was always wound positively; measured, a +180° sweep came out at +3036 square units and
  −180° at −3036. A band crosses whatever it is drawn over, so under `nonzero` the sign of the sweep
  decided whether the two merged or cancelled — 21 of 42 sweep and size combinations erased the shape
  underneath. The outer arc is now walked with increasing angle whichever way the caller sweeps, so the
  winding is pinned without the geometry moving. A test that asserted the old flip was _intended_, on the
  grounds that reversing the trace keeps a gauge's counter filled, has been replaced: counters come from
  `ringPath` opposing its two ellipses, and one band's orientation has no bearing on them.
- **Abstract marks were centred on their construction rather than on their ink.** This was deliberate and
  recorded in the architecture doc — an orbit is centred on a circle, not on a square. It was the wrong
  trade. A mark centred on the wrong thing reads as _loose_ rather than as designed, and nobody can say
  why. Measured across the original five modes, the worst sat 69.6 units off centre on a 512 canvas,
  14% of its width, with `orbit` at 35.0, `arcs` at 31.5 and `waves` at 23.4. The engine now measures its
  ink and translates the composition to centre it. Geometry is unchanged, so a mark still reads as an
  orbit; it now also sits centred.
- **The abstract engine collapsed its three fill roles onto one colour.** Roles were resolved one at a
  time, each falling back to the role before it, so a palette whose accent equals its background pushed
  `second` onto `lead` and `third` onto both. On `azure-current` — whose accent is literally `#f0f9ff` on
  an `#f0f9ff` background — every mark came out a single flat tone, and the modes that build depth from
  layered tones lost the one thing they are for. Roles are now drawn from the palette as a set, rejecting
  a candidate that is illegible _or_ already spoken for.

### Added

- **Ten abstract modes, for space and technology briefs.** `lattice` (a dot grid filling along a
  diagonal), `gridframe` (a coordinate crosshair), `portal` (one-sided signal arcs), `helix` (two
  interleaved strands joined by rungs), `aperture` (an iris), `prism` (nested polygons), `scatter` (a
  tidy `orbit`), `meridian` (a globe), `chevrons` (a signal stack) and `stacked` (nested squares). Two
  rules keep the set coherent rather than merely larger: depth is built from layered tone, because
  gradients and shadows are banned; and every mode is measured rather than eyeballed — a mark that cannot
  be centred by measurement is a mode that does not get added.

### Fixed

- **`fileStem` dropped the letter a diacritic was on.** The slug was built by replacing every character
  outside `[a-z0-9]` with a hyphen, which removed accents _and_ the vowels carrying them: "Café Über"
  became `caf-ber`. The name now normalises to ASCII first, so it becomes `cafe-uber` and only the marks
  are lost. Folding still converges "Café" and "Cafe" on purpose — they are the same brand to a reader —
  but two genuinely different names no longer collide.

### Fixed

- **The studio did not respond to viewport width at all.** The three-column layout is 288 + 300 units of
  fixed, non-shrinking panels beside the stage. At a 390px phone they consumed the entire viewport: the
  stage was squeezed to zero width and the right panel's text was cut off mid-word. Below 900px the panels
  now overlay the stage as drawers, only one at a time — two open at once would cover the mark, which is
  the one thing the app exists to show. Narrowing records which panels were open and closes them; widening
  puts them back.
- **A panel toggle could be buried under the drawer it opens.** The toggles sat below the panels in the
  stacking order, which was harmless while the panels were columns and fatal once they were overlays: the
  toggle was unreachable and the drawer could not be closed at all.
- **The title bar clipped its own brand.** The brand, two segmented controls and the primary button need
  about 420px between them. Below `sm` the controls now take a full row, costing 24px of height only where
  there is height to spare.
- **The concept strip could overflow the page.** Six 64px tiles plus gutters need about 440px; the row
  scrolls sideways instead of compressing past being clickable.
- **`Segmented` claimed `role="radiogroup"` without honouring it.** It is a contract, not a label: one tab
  stop, arrow keys to move, selection following focus. Every segment was its own tab stop, so a reader
  crossing the studio passed through eight stops to get from the language control to the theme control, and
  the arrow keys a screen reader announces as available did nothing. Arrow keys, `Home`/`End` and wrapping
  now work, and a group whose stored value matches no option still has a tab stop rather than becoming
  unreachable by keyboard.
- **`vitest.config.ts` and `tsconfig.json` had drifted apart.** The studio's aliases were declared in both
  places, and `tsconfig` used one wildcard where the test config enumerated five entry points. A sixth
  import — `@sigilgen/text`, pulled in by `font-sample.ts` — typechecked, built and ran in the browser, and
  failed only under test. The test config now derives its aliases from `tsconfig.json`, which makes that
  class of drift impossible rather than merely unlikely.

### Changed

- **The mark sits on a sheet.** The stage was an edge-to-edge fill, which puts the artwork in the middle
  of a large undifferentiated rectangle and reads as an unfinished canvas rather than a presentation. The
  paper is now a square, inset, rounded and lifted — an artboard on a desk, the way macOS presents a photo
  or a document. The backdrop options moved onto the sheet, which is the surface the palette's colours
  were chosen against.
- **The disclosure row was 20px tall.** Beside 32–35px controls, and the only route to 121 resources, it
  was both hard to hit and visually inconsistent. It is now a full 32px row with hover and focus
  treatment, using negative margins so the extra room costs the layout no horizontal space.
- **The concept strip reads as a sequence.** Tiles are 68px with more air and a slightly stronger resting
  opacity; the selected tile keeps its number visible and the others reveal theirs on hover.

### Fixed

- **Accented letters were deleted rather than folded.** `normaliseLetters` filtered straight to `A`–`Z`,
  which removes the _letter_ along with the accent: `Café` drew `CAF`, `Über` drew `BER`, `Növa` drew
  `NVA` — a mark reading a different word, from a name the reader had typed correctly. Names are now
  decomposed and only the combining marks are dropped, so the letter survives. The handful of letters
  Unicode will not decompose (`Æ`, `Ø`, `Ł`, `Ð`, `Þ`) are mapped explicitly, and `ß` is expanded by
  `toUpperCase` on its own. Neither step is locale-sensitive, so determinism is unaffected.

  This is the same defect as the studio's `fileStem` dropping the letter under an accent, found in the
  core this time, and it had been there for the whole project.

- **`generate()` threw when `preferences` was omitted.** `StudioConfig` declares the field as required,
  which is right for the store's state, but the implementation assumed it: `Object.keys(undefined)` raises a
  `TypeError` that says nothing about which field was wrong. The app never hit it because the store always
  carries the key; any caller assembling a configuration by hand did.

### Added

- **An accented name in the determinism manifest.** None of its ten cases contained a character outside
  `A`–`Z`, which is why the fix above changed the manifest's fingerprint from nothing at all — a change
  to how letters are derived passed that check untouched while quietly redrawing every accented name.
  The eleventh case is `Café Über`, so this cannot recur silently.

### Added

- **A test suite for the studio.** `apps/web` had roughly two thousand lines of React and TypeScript, a
  stateful store with persistence, and a hand-rolled i18n layer, and not one test — while `pnpm run check`
  only linted, formatted and typechecked it. It has its own Vitest configuration, its own gate, and tests
  for the store, persistence, the provider, the primitives and the layout.
- **`apps/web/README.md`.** The studio had no documentation of its own, so the things a contributor has to
  know before touching it — that it is a separate package the root gate does not cover, that it imports
  the library's _source_ so its aliases are declared twice and must agree, and that it stores absence
  rather than a sentinel — were only discoverable by reading it.

Three more centring defects, found the same way as the four below: by generating across a wide input
space and measuring the ink bounding box of every result against the canvas. All three share one cause
— a layout was centred on the **room reserved** for its contents rather than on the **ink those
contents actually draw**.

- **The emblem banner sat a twentieth of the canvas high.** `frameBox` gave the banner a box from
  `-0.72r` to `+0.56r`, whose centre is `-0.08r`, while the shield, hexagon and circle are all exactly
  `-r..+r`. Combined with the interior fault below, a banner emblem's ink was **6.88% of the canvas
  off centre** — the worst misalignment in the library, on every single emblem.
- **A badge's contents were centred on their slots, not their ink.** The name is fitted into a band
  reserved for it, but a long name in a narrow frame comes out far shorter than that band, and the
  interior was then centred on the band. Icon and name together sat high by about a fifth of the way
  out of the block's centre, while each individual slot was placed exactly where the table said. Both
  are now placed on the ink, with the clear gap the table asked for hung off the pictogram's ink.
- **A vertical wordmark was placed against a block its own contents did not fill.** Two independent
  reasons: a long name is bound by width and comes out shorter than the band reserved for it, and
  `placeIcon` scales by the _larger_ of a pictogram's two extents, so a pictogram narrower than it is
  tall is letterboxed and its ink is shorter than the box too. `Northwind Coffee` in a vertical lockup
  came out **5.79% of the canvas low**.

The underlying gap was that no engine could ask how big a thing's ink is. `measureText` answers a
different question — how wide the advance boxes are — and the two differ by the outer side bearings
and, in height, by however far the letters fall short of the cap line. New `textInk` measures the
answer, and `iconInkSize` exposes the same for a pictogram from the same computation `placeIcon` uses,
so the two cannot disagree. `fitText` now centres both axes on the measured ink, which also retired its
half-tracking-unit fudge factor. Measured worst case across the monogram, wordmark and emblem engines,
over 1650 input cases and 3434 generated marks: **under 0.25% of the canvas**, where it was 6.88%.

#### Arc bands wound against the strokes, and every bowl letter carried a seam

An arc band's winding used to depend on which way round its sweep ran, so a band cancelled against every
stroke it overlapped. `B`, `D`, `P` and `R` each carried a seam down the side where their bowl met their
stem, and `J`'s hook had one too in the serif families.

Three things made this hard to see, and each is worth recording because the obvious check misses all three:

- **A bounding box cannot see it.** The stem beside the seam reaches the cap line and the baseline
  perfectly well, so the letter's extent is correct. The defect is inside the ink.
- **The counter-sampling cannot see it either.** It samples the middle of a bowl, which is a legitimate
  counter. A seam is neither a counter nor out of bounds.
- **The direction is not visible in the letter.** A band wound the other way looks identical; it only
  differs where it overlaps something. So the damage tracked the sweep each letter happened to ask for,
  which is why it looked like some bowls were fine and some were not.

`arcBand` now pins the outer arc to one direction and the inner arc to the other, whichever way the caller
sweeps, and the pinned direction is the one that matches `stroke`. Which one that is, is not a matter of
taste and cost a wrong turn to establish: a stroke winds −1, and an outer ellipse walked with increasing
angle winds +1, so the first attempt pinned the wrong way and changed nothing. The winding numbers say it
directly — `ring`'s outer contour is +1 and the stem beside it is −1.

`B`'s bowls also turned out to be a half stroke inside both edges, because `bowl` passed its rows straight
to `arcBand` and never went through `reach`. The rows are read back as edges now. `B`'s bowls measure
`0..357` and `343..700` where they were `55..357` and `343..646`.

The winding guard in `tests/brain.test.ts` now covers `B`, `D`, `P`, `R` and `J` as well. They are letters
with counters, and they are in the set because their counters come from a single band contour rather than
from an opposite-wound pair — which is exactly what let them regress. Verified to fail against the pre-fix
build: `orbit-grotesk B at 88,2`.

#### Capitals did not reach the cap line or the baseline

Found while measuring, in the same pass. Fixed here.

Letters that do not share a baseline do not read as set at all, and the error scales with the mark — it
was worst at exactly the sizes a logo is used at. Measured in `orbit-grotesk` (cap 700) against the
rules at 0 and 700: `L` stopped 55 units below the cap line, `S` 63 above the baseline, `I` floated 55
clear at each end, and every letter of `slab-serif` sat between 62 and 72% of cap height. `SALVO` in one
family spanned 39 points of cap height from its shortest letter to its tallest.

`stroke` returns a butt-ended quad, so it reaches exactly as far as its centreline and no further.
`buildGlyphs` therefore insets every endpoint by half a stroke and closes the gap with a terminal disc.
Five things had to be true for that to work, and each was wrong:

- **`capRound` returned an empty string for any family with `round: false`** — and `round` was read
  nowhere else, so the flag was not choosing a terminal style, it was choosing whether a terminal
  existed. Ten of the eighteen families were drawn with their terminals missing. The disc is now
  unconditional and the flag is gone: a geometric sans with softly rounded terminals is idiomatic, and
  it is the only arrangement whose geometry is expressible. Running a butt end to the edge instead would
  need a different inset on the vertical axis than the side bearing uses, plus an audit of every
  diagonal, since a butt end on a diagonal does not reach the same row a disc does.
- **The disc wound the other way from the stroke.** It is centred on an endpoint, so half of it lies
  inside the stroke's own rectangle, and the non-zero fill rule only keeps that overlap filled if the two
  sub-paths wind alike. Wound the other way, every terminal in the library punched a white notch through
  its own stem. A bounding-box test cannot see this and neither can the existing counter-sampling, because
  a terminal is neither out of bounds nor a counter. A new guard asserts that filling a glyph as one path
  agrees with filling each sub-path and taking the union; the two differ exactly where opposite windings
  overlap. Verified to fail against the pre-fix build.
- **A junction is not a terminal.** `U`'s stems end inside the bowl, and a disc there overlaps a band
  wound the other way. `stem` takes a `freeTo` flag for that.
- **The slab sat centred on the stem's endpoint** rather than against the cap line or the baseline, which
  is why the four serif families came out lowest of all.
- **`inset` was doing double duty** as both the side bearing and the terminal inset, so a serif overhang
  — which should only widen a letter — was also lowering its cap line. The vertical half is now `vInset`.

Two arc-built letters needed geometry of their own. `U`'s bowl stopped a half stroke above the baseline,
because `arcBand` measures its thickness inward, so the outer edge is at `ry`. And `S`'s lower bowl swept
130 degrees from 40 to -90, the short way round, which never passes the bottom of its own ellipse — so
`S`'s lowest point was its lower-right terminal. It sweeps 230 now.

All eighteen families now measure exactly 100% of cap height on all twenty-five cap-only letters, so the
spread inside a word is zero points of cap height. `Q` is excluded: its tail is a descender and is meant
to pass the baseline, as a round letter is meant to overshoot the cap line.

#### Previously

Four alignment defects, all found by measuring the ink bounding box of real output against the canvas
rather than by eye. The worst case was 18.5% of the canvas off centre.

- **A wordmark's two words were set as one.** `measureText` counted a space at the missing-glyph
  fallback advance while `textPath` skipped it entirely, so `Northwind Coffee` was measured with a gap
  and drawn without one: `NORTHWINDCOFFEE`. Measurement and drawing now resolve every advance through
  one function, and an undrawable character leaves the gap it was measured as. A word space is 0.26 em
  rather than the full capital it fell back to.

- **The horizontal wordmark lockup was flush left.** The pictogram was pinned to the canvas margin and
  the name centred in whatever was left over, so all the slack collected on the right and the mark
  drifted up to 11% of the canvas off centre. The lockup is now centred as a whole, which means fitting
  the name before placing anything — its width is what the left edge depends on.
- **Centring an advance box does not centre the run.** The compiler gives every glyph equal side
  bearings, so the bearings cancel, but the last letter's advance is counted while its glyph stops at
  the bearing. The ink therefore sat half a tracking unit left of where the run was asked to be
  centred — up to 4.1% of the canvas on a tight-tracked lettermark. `fitText` now shifts by that half
  unit. Measured worst-case drift across all 18 typefaces is now under 0.25% of the canvas.
- **Arc bands all left from the same part of the ring.** Starting angles were staggered by 18–42°
  instead of around the circle, so three or four concentric arcs overlapped into one lopsided fan and
  left up to 18.5% of the canvas empty on one side. They now start a third of a circle apart, which is
  what they were meant to read as. The orbit mode's satellite count also starts at three: two dots on
  opposite sides of a centred ring is the same shape as one dot and its shadow.
- **Letters came apart, and words ran together.** Two separate causes, both spacing metrics that were
  absolute numbers where they needed to be proportional.
  - Side bearings were authored per family in font units, so a 66-unit gap meant wide air on a
    46-unit stem and near-contact on a 241-unit slab. Measured across the library the gap between
    letters ranged from 34 to 345 thousandths of cap height, and the light geometric faces read as
    `N O R T H W I N D` rather than as a word. The compiler now derives the bearing from the stroke,
    sub-linearly so a heavy face gets proportionally less air, and keeps each family's authored
    `sideBearing` and `tracking` as fractions so no face loses its character. The range is now 68–117.
  - The word space was a fixed 0.26 em, which is narrower than the gap between letters in the loosest
    family — so `Northwind Coffee` came out as one word in some faces and two in others, and
    `stipple-display` measured a word gap of 0.06× its letter gap. The space is now compiled into each
    family's `advance` table, sized against that family's own letter gap, and every family measures
    2.2×.
- **Engines derived tracking from an authoring constant.** `wordmark`, `lettermark`, `monogram` and
  `emblem` all scaled `font.letterSpacing`, which is the number the compiler happened to use when
  deriving bearings and has no relationship to the spacing they produce. Since tracking is added to
  every advance, one unit widens the gap by exactly one unit, so the same multiplier put a wordmark's
  gap at 309 thousandths of cap height in one family and made a lettermark's letters overlap in
  another. All four now express optical tracking through `opticalTracking(font, fraction)` as a
  fraction of cap height, which is the unit letterspacing is actually specified in.
- **Half the library was set at hairline weight.** Nine of the eighteen families were authored between
  6.6% and 9.1% of cap height, which is hairline territory — a Regular sans is 12 to 14%. A text face
  can get away with that; a logo cannot. At the size a wordmark fits an eighteen-character name into, a
  7% stroke is barely two pixels, and it is gone by favicon size, which is the size a mark has to
  survive. The library now spans 12.5% to 22% — Regular to heavy — with the nominal weights kept so the
  intended light-to-heavy ordering survives. `tests/brain.test.ts` already sampled the winding number
  inside the counters of seven letters across all eighteen families, so raising the weight could not
  quietly close a bowl in `B`, `R`, `P` or `A`; it did not.

## [1.0.0] — 2026-10-04

First stable release.

### Added

- **Deterministic generation pipeline.** `generateLogo` and `generateLogos` turn a brand name plus
  keywords into one to six flat geometric SVG concepts. Identical input always produces
  byte-identical output.
- **Five rendering engines.** `monogram`, `wordmark`, `lettermark`, `abstract` and `emblem`, each
  producing a different structural interpretation of the same input.
- **Curated JSON brain.** 33 palettes, 18 typeface families with 468 pre-generated glyph outlines,
  70 pictograms, and 34 mood rules that map keywords to a coherent set of resources. The data ships
  inside the bundle, so loading it costs nothing at runtime.
- **Key-driven deterministic randomness.** A dependency-free SHA-256 implementation feeds a
  reproducible numeric stream, so every "random" choice is reproducible across platforms and Node
  versions without importing `node:crypto`.
- **`sigilgen` CLI.** Deterministic SVG on stdout, `--output` for files, `--json` for a
  machine-readable summary, and optional `--png` rasterisation via `sharp`.
- **Optional PNG rasterisation.** `rasterise()` and `--png`, loaded dynamically so `sharp` is only
  needed by callers who actually want a bitmap.
- **A serializer that is the trust boundary.** Allow-listed elements and attributes, quoted values,
  and rejection of anything that could inject markup. Untrusted input — brand names, keywords,
  briefs, colour lists — is never emitted verbatim.
- **Parametric letterform compiler.** `scripts/build-brain.mjs` compiles outlines from geometric
  skeletons into cubic Béziers, so type is generated rather than licensed.
- **Community health files.** MIT `LICENSE`, `README`, `CONTRIBUTING`, `CODE_OF_CONDUCT` (link-only),
  `SECURITY`, this changelog, issue templates, a PR template, and CI.
- **396 tests** covering determinism, flatness, escaping, brain integrity, routing, glyph data,
  engine output and the CLI.

### Fixed

- **Overlapping monograms were drawn off centre and could leave the canvas.** The overlap layout
  measured a narrowed box but drew the full-width run, so the letters were shifted right by a third of
  the difference and a wide pair could reach past the canvas edge. Overlap now comes from the tracking,
  and the run is additionally scaled to the width its container actually offers — a hexagon's flanks
  stand at `0.866 ×` its radius, so measuring against its bounding box let letters poke through.
- **`pathBounds` measured every curve wrongly.** `parsePath` stores a cubic as two control points and
  an end point, with the start point implied by the current position, but the measuring code read those
  six values as though the start were included. Every curve was therefore measured shifted by one
  control point, so bounding boxes were too large — most visibly in icon placement, where each pictogram
  was scaled to the wrong size. It also evaluated only x's turning points, missing the top and bottom of
  any curve that is steep there. Both are now asserted directly.
- **Glyph metrics put all the spacing on one side.** Advances came from the skeleton's nominal box
  width rather than the glyph's measured ink, and the ink was never shifted, so every letter had a left
  bearing of about zero and a large right one. A centred single letter therefore sat visibly off-centre,
  and `J` overshot its advance by enough to collide with the letter before it. The compiler now measures
  each glyph's ink — with the same exact turning-point solve the runtime uses — derives the advance from
  that, and centres the ink between equal side bearings. The build fails if any glyph's ink leaves its
  advance box or if its bearings are unequal.
- **Emblem names no longer escape their frame.** The banner's layout was derived from `size` fractions
  while the banner outline was derived from the centre and radius, so the icon and name were positioned
  against a rectangle the frame did not occupy. Both now read one `frameBox`, and the name is fitted to
  the narrowest row of the frame across the band it occupies rather than to a hand-tuned width, so a
  tapered shield or a notched banner cannot leave the type hanging outside its own badge. The banner
  also keeps its name inside the flag, where the reversed-out colour is guaranteed to read.
- **Lettermark corner frames are drawn in the right direction.** The four brackets are built from the
  endpoints of each edge of a square, but were handed to a horizontal-only capsule helper, so the two
  vertical brackets were drawn as horizontal bars and landed outside the frame. New `segmentPath`
  primitive takes its direction from the endpoints.
- **Font selection honours the engine's category rules in every fallback.** `SeedResolver.choice` picks
  uniformly by index, so ordering candidates by preference never made a category any more likely — only
  filtering the pool does. The last-resort branch sorted the whole brain and picked from it, so a mood
  naming no fonts could hand a letter mark a didone, the one outcome the rules exist to prevent.
- **`check:determinism` can no longer report a false pass.** The check imports the built bundle, so
  running it against a stale `dist` re-hashed the old output and reported success no matter what the
  source said. It now refuses to run when `src` is newer than the build.

### Changed

- Letter normalisation is now a single documented rule (`normaliseLetters`) instead of four copies of
  the same inline expression, so the stages that decide which letters a mark may draw cannot drift
  apart.
- Removed dead code: `selectLetters`, `rect`, `centredText`, `scaleForCapHeight`, `lettersOnly`,
  `dividerRule`, `pathSize` and `engineUsesIcon` were unreachable from any engine and from the public
  API.
- Added `pnpm run test:coverage:gaps`, which prints uncovered line ranges per file so coverage numbers
  can be judged against reachable behaviour rather than in the abstract.
- Glyph geometry is now checked by filling it: a winding-number sampler in the test suite asserts that
  every letter drawn with a counter has one, that letters are not mostly hollow, and that no stray
  sub-path inflates a glyph. The sampler is itself checked against a solid disc and a ring first, so a
  pass cannot come from a broken measurement.

### Security

- The serializer rejects `<script>`, event-handler attributes, external references, `style`, and every
  element and attribute outside its allow-list. Attribute values are validated against conservative
  patterns and only then escaped.
- The CLI resolves and creates its output directory before writing, and only ever appends the
  extensions it advertises. File stems are slugified, so a name like `../../etc/passwd` cannot escape
  the output directory.
- Input length is bounded for names, keywords, briefs, word counts and canvas sizes, so hostile input
  cannot stall the pipeline.
