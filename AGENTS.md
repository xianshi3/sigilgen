# Sigilgen — AI Agent Guidelines

> This file is the **single source of truth** for AI coding agents working on this repository.
> Every tool-specific file (`CLAUDE.md`, `.cursorrules`, `.windsurfrules`,
> `.github/copilot-instructions.md`) is a symlink to this file. Never edit those; edit this.

## What Sigilgen Is

A deterministic, offline, flat-geometric SVG logo generator. Input is a brand name plus keywords;
output is 1–6 SVG concepts. Identical input always yields byte-identical output. All design
decisions come from a curated JSON knowledge base ("the brain"), never from an AI model or a
network call.

no test is a defect; an unreachable defensive fallback is not. Prefer deleting dead code over testing
it.

## Commit and PR Conventions

Conventional Commits: `<type>(<scope>): <summary>`

- Types: `feat`, `fix`, `perf`, `docs`, `test`, `refactor`, `chore`, `ci`, `build`, `style`
- SemVer: `feat` → minor, `fix`/`perf` → patch, everything else → none
- Breaking changes: `feat(cli)!: ...` or a `BREAKING CHANGE:` footer. Either forces a major bump.
- Scope should name the area: `engines`, `resolver`, `brain`, `cli`, `serializer`.
- Summary in imperative mood, ≤ 72 characters, no trailing period.

## Architecture Summary

JSON Brain driven deterministic generation pipeline.

```text
LogoConfig
  → SeedResolver        hash(name, keywords, seed) → deterministic numeric stream
  → MoodResolver        keywords/brief → MoodMatch (mood rules + notes)
  → EngineRouter        mood weights + name length → engine id
  → Resolvers           FontResolver / PaletteResolver / IconResolver → Brain resources
  → Engine              SVGElement[] (pure geometry, no I/O)
  → SVGSerializer       SVGElement[] → flat SVG string
  → LogoResult
```

### Hard Constraints

These are the invariants the test suite enforces. Breaking one is a bug, not a trade-off.

1. **Zero runtime dependencies.** `dependencies` is `{}`. `sharp` is the only optional package and
   only the PNG path may import it, via dynamic `import()`.
2. **Byte-identical output.** Same input ⇒ same bytes. Banned: `Date.now()`, `Math.random()`,
   `crypto.randomUUID`, locale-sensitive comparisons (`toLocaleUpperCase`, `localeCompare`), and any
   reliance on `Object`/`Set`/`Map` iteration order for numeric choices.
3. **Flat SVG only.** Emitted SVG contains no `<linearGradient>`, `<radialGradient>`, `<filter>`,
   `<mask>`, `<clipPath>`, `<pattern>`, `<image>`, `<foreignObject>` or `<script>`, and no `on*`
   event attributes.
4. **Font paths come from the JSON brain.** Never parse a font file at runtime. No `opentype.js`,
   no `measureText`, no canvas.
5. **Untrusted input is escaped or rejected.** Brand names and keywords are attacker-controlled.
   See the escaping contract in `src/serializer.ts`.
6. **No import cycles.** `import/no-cycle` is an error. Engines never import the router; the router
   imports engines. Engines never import resolvers — they receive resolved resources as arguments.

### Determinism Rules

- Every random-looking decision must come from a `SeedResolver` stream.
- When picking from a keyed object, sort keys first, then choose by index.
- Format numbers through `src/format.ts` (`fmt`) so output is stable across platforms.
- Node's `Number.prototype.toFixed` is deterministic; `String(0.1 + 0.2)` style output is not
  acceptable inside a path string.

## Testing Rules

- Location: `tests/`
- Naming: `<module-name>.test.ts` (mirrors the module under test)
- Framework: Vitest 3, `describe`/`it`/`expect`, `vi` for mocks
- Use `vi.fn()` for spies, `vi.mock()` only when a real mock would be brittle

Required test coverage:

| Test kind        | What it asserts                                      | Required |
| ---------------- | ---------------------------------------------------- | -------- |
| Determinism      | Identical inputs produce byte-identical SVG          | yes      |
| Seed stream      | Identical inputs produce identical float sequences   | yes      |
| Engine routing   | Short names favour monogram/lettermark               | yes      |
| SVG validity     | Output parses as XML                                 | yes      |
| Flatness         | No gradient/filter/mask/script/handler output        | yes      |
| Escaping         | Quotes, `<`, `&`, `url(` cannot escape attributes    | yes      |
| Glyph data       | Every referenced glyph has valid path data           | yes      |
| Brain integrity  | Every mood references existing palette/font/icon ids | yes      |
| Input validation | Clamping and rejection of bad configs                | yes      |

## Code Style

oxc-standard (oxlint + oxfmt), Standard Style:

- No semicolons, single quotes, 2-space indent, 100-column width, `arrowParens: avoid`
- `interface` over `type` for object shapes (`typescript/consistent-type-definitions`)
- `Array<T>` over `T[]` (`typescript/array-type`)
- `import type` for type-only imports (`typescript/consistent-type-imports`)
- No `any` anywhere (`typescript/no-explicit-any` is an error)
- JSDoc on every exported symbol
- `tsconfig` runs `strict` plus `noUncheckedIndexedAccess`, `noUnusedLocals`,
  `noUnusedParameters`. Treat `undefined` from index access as real.

## Definition of Done

A change is done when all of the following hold:

- `pnpm run check` passes locally.
- New behaviour has a test; changed behaviour has an updated test.
- Determinism, flatness and escaping tests still pass untouched.
- Public API or CLI changes are reflected in `README.md` and JSDoc.
- Commits follow Conventional Commits; the PR description states _why_, not just _what_.
