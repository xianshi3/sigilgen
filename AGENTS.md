# Sigilgen — AI Agent Guidelines

> This file is the **single source of truth** for AI coding agents working on this repository.
> Every tool-specific file (`CLAUDE.md`, `.cursorrules`, `.windsurfrules`,
> `.github/copilot-instructions.md`) is a symlink to this file. Never edit those; edit this.

## What Sigilgen Is

A deterministic, offline, flat-geometric SVG logo generator. Input is a brand name plus keywords;
output is 1–6 SVG concepts. Identical input always yields byte-identical output. All design
decisions come from a curated JSON knowledge base ("the brain"), never from an AI model or a
network call.

no test is a defect; an unreachable defensive fallback is not. Prefer deleting dead code over testing
it.

## Commit and PR Conventions

Conventional Commits: `<type>(<scope>): <summary>`

- Types: `feat`, `fix`, `perf`, `docs`, `test`, `refactor`, `chore`, `ci`, `build`, `style`
- SemVer: `feat` → minor, `fix`/`perf` → patch, everything else → none
- Breaking changes: `feat(cli)!: ...` or a `BREAKING CHANGE:` footer. Either forces a major bump.
- Scope should name the area: `engines`, `resolver`, `brain`, `cli`, `serializer`.
- Summary in imperative mood, ≤ 72 characters, no trailing period.

## Architecture Summary

JSON Brain driven deterministic generation pipeline.

```text
LogoConfig
  → SeedResolver        hash(name, keywords, seed) → deterministic numeric stream
  → MoodResolver        keywords/brief + name words → MoodMatch (mood rules + notes)
  → EngineRouter        mood weights + name length + name cue → engine id
  → Resolvers           FontResolver / PaletteResolver / IconResolver → Brain resources
  → Engine              SVGElement[] (pure geometry, no I/O)
  → SVGSerializer       SVGElement[] → flat SVG string
  → LogoResult
```

A **scene** is a separate document, not a tenth engine. It bypasses the router and the brain's mood
rules, and goes straight from `LogoScene` to the same `SVGElement` and serializer boundary:

```text
LogoScene
  → normaliseScene      validate, assign ids, default, clamp
  → sceneToSvgElements  flat shapes, text compiled from font outlines, pictograms from the brain
  → serialiseDocument   same allow-list and escaping as the generator
  → SVG string
```

### Hard Constraints

These are the invariants the test suite enforces. Breaking one is a bug, not a trade-off.

1. **Zero runtime dependencies in the root package.** `dependencies` is `{}`. `sharp` is the only
   optional package and only the PNG path may import it, via dynamic `import()`. The app packages
   (`apps/web`, `apps/mcp`, `apps/desktop`) carry their own dependencies — React and motion, the MCP SDK
   and `zod`, Electron — because they are deployed surfaces, not the library. Nothing here may leak
   into `src/`. `@mdi/js` is a devDependency used only by `scripts/build-icons.mjs`; its path data is
   committed as `src/brain/icons.json`.
2. **Byte-identical output.** Same input ⇒ same bytes. Banned: `Date.now()`, `Math.random()`,
   `crypto.randomUUID`, locale-sensitive comparisons (`toLocaleUpperCase`, `localeCompare`), and any
   reliance on `Object`/`Set`/`Map` iteration order for numeric choices.
3. **Flat SVG only.** Emitted SVG contains no `<linearGradient>`, `<radialGradient>`, `<filter>`,
   `<mask>`, `<clipPath>`, `<pattern>`, `<image>`, `<foreignObject>` or `<script>`, and no `on*`
   event attributes.
4. **Font paths come from the JSON brain.** Never parse a font file at runtime. `fontkit` runs at build
   time only (`scripts/glyph-source.mjs`), against the OFL fonts vendored in `assets/fonts/`; nothing in
   `src/` reads a font, and no `measureText` or canvas is used anywhere. Runtime dependencies stay empty —
   `fontkit` is a devDependency and its output is committed as `src/brain/fonts.json`.
5. **Untrusted input is escaped or rejected.** Brand names and keywords are attacker-controlled.
   See the escaping contract in `src/serializer.ts`.
6. **No import cycles.** `import/no-cycle` is an error. Engines never import the router; the router
   imports engines. Engines never import resolvers — they receive resolved resources as arguments.
7. **Winding is part of the output contract.** With no `mask` and no `clipPath`, the only way a hole is
   cut is a sub-path wound against its parent. Two overlapping shapes that wind alike merge; two that
   wind against each other erase one another under `fill-rule: nonzero`. **Every primitive must pin its
   winding** rather than inherit it from the order the caller happened to ask for — `arcBandPath`,
   `ringPath`, and the glyph compiler's bands and apex wedges all do. A winding bug is invisible to a
   bounding box, because the geometry _around_ the hole is correct; it shows only as a seam, a gap or a
   notch. Test orientation by signed area, and test overlap by sampling the overlap itself.
8. **A mark is centred on its measured ink.** Not on the layout box, and not on the construction that
   built it. All three differ, and only the first is what a reader sees. Centring on the box leaves a
   bearing's width of slack on one side; centring on the construction leaves an orbit whose satellites
   happen to fall one way pushed off to one side.

### Studio Layout Contract

These are enforced by `apps/web` tests, and they are about what a reader sees rather than style taste.

- **Both side panels share one width** (`PANEL_WIDTH`, 300px). Unequal widths shift the stage, the
  titlebar island and the sheet off the window's centre.
- **The narrow breakpoint is derived** from the panel widths plus `MIN_STAGE_WIDTH` (currently 1020px).
  Never type a breakpoint literal into a class; branch on `narrow` or use the exported constants.
- **Scrollbar gutters belong to scroll containers** (`.scroll-gutter`), never to `html`. A stable gutter
  on the document reserves about 10px on the right of the window even when nothing scrolls, which makes
  the side margins asymmetric.
- **The desktop shell adds a 38px strip above this layout** on Windows and macOS; it must not change the
  studio's internal widths or breakpoint.

### Studio Editing Contract

- **Snapping is measured in screen pixels.** Six of them, so the gesture feels the same at every zoom.
  A drag captures the sheet's left/centre/right and top/middle/bottom plus every other visible part's,
  and draws a guide only on the axis it captured.
- **The guide toggle is persisted.** It belongs beside the design, not with transient view state: a
  reader who turned it off did so deliberately.
- **A snap that changes nothing is not an edit.** The undo snapshot is taken when the part first moves,
  not when the pointer first moves.
- **Draw mode is a workspace, not a layout.** It swaps the panels and the stage content but keeps the
  same 300px panel widths, derived breakpoint, sheet, zoom, backdrops and alignment guides. A scene is a
  document (`src/scene.ts`), not a tenth engine; do not route it through the mood rules.

### Determinism Rules

- Every random-looking decision must come from a `SeedResolver` stream.
- When picking from a keyed object, sort keys first, then choose by index.
- Format numbers through `src/format.ts` (`fmt`) so output is stable across platforms.
- Node's `Number.prototype.toFixed` is deterministic; `String(0.1 + 0.2)` style output is not
  acceptable inside a path string.

## Testing Rules

- Location: `tests/` for the library, `apps/web/tests/` for the studio, `apps/desktop/tests/` for the
  shell
- Naming: `<module-name>.test.ts` (mirrors the module under test); `.test.tsx` where JSX is involved
- Framework: Vitest 3 in all three, pinned to the same major — a second runner version is a trapdoor
- The library suite runs in `node`; the studio suite runs in `jsdom` and covers persistence, clipboard
  and locale, which are unreachable from the library's environment; the desktop suite runs in `node`
  and covers the pure geometry, validation and localization rules behind the window
- Use `vi.fn()` for spies, `vi.mock()` only when a real mock would be brittle

Required test coverage:

| Test kind        | What it asserts                                      | Required |
| ---------------- | ---------------------------------------------------- | -------- |
| Determinism      | Identical inputs produce byte-identical SVG          | yes      |
| Seed stream      | Identical inputs produce identical float sequences   | yes      |
| Engine routing   | Short names favour monogram/lettermark               | yes      |
| SVG validity     | Output parses as XML                                 | yes      |
| Flatness         | No gradient/filter/mask/script/handler output        | yes      |
| Escaping         | Quotes, `<`, `&`, `url(` cannot escape attributes    | yes      |
| Glyph data       | Every referenced glyph has valid path data           | yes      |
| Brain integrity  | Every mood references existing palette/font/icon ids | yes      |
| Input validation | Clamping and rejection of bad configs                | yes      |
| Scene rendering  | Same scene → same SVG; flat, safe, palette roles     | yes      |
| Scene editing    | Add/move/reorder/delete survive undo and reload      | yes      |

## Code Style

oxc-standard (oxlint + oxfmt), Standard Style:

- No semicolons, single quotes, 2-space indent, 100-column width, `arrowParens: avoid`
- `interface` over `type` for object shapes (`typescript/consistent-type-definitions`)
- `Array<T>` over `T[]` (`typescript/array-type`)
- `import type` for type-only imports (`typescript/consistent-type-imports`)
- No `any` anywhere (`typescript/no-explicit-any` is an error)
- JSDoc on every exported symbol
- `tsconfig` runs `strict` plus `noUncheckedIndexedAccess`, `noUnusedLocals`,
  `noUnusedParameters`. Treat `undefined` from index access as real.

## Definition of Done

A change is done when all of the following hold:

- `pnpm run check` passes locally.
- New behaviour has a test; changed behaviour has an updated test.
- Determinism, flatness and escaping tests still pass untouched.
- Public API or CLI changes are reflected in `README.md` and JSDoc.
- Commits follow Conventional Commits; the PR description states _why_, not just _what_.
