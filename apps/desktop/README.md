# Sigilgen Desktop

The native desktop client for Sigilgen. It is a shell around the studio in [`apps/web`](../web), not
a second interface: the same React components, the same generator bundle and the same tests. The shell
adds what a browser cannot give it — a real window, a native menu, a native Save dialog, a clipboard
that works outside a secure context, and a place to remember the window geometry.

## Download

The current build is published on [GitHub Releases](https://github.com/xianshi3/sigilgen/releases).
The 0.1.0 assets are:

| Platform              | Asset                                                                 |
| --------------------- | --------------------------------------------------------------------- |
| Windows x64           | `Sigilgen-0.1.0-setup-x64.exe` or `Sigilgen-0.1.0-portable-x64.exe`   |
| macOS (Apple silicon) | `Sigilgen-0.1.0-mac-arm64.dmg`                                        |
| macOS (Intel)         | `Sigilgen-0.1.0-mac-x64.dmg`                                          |
| Linux x64             | `Sigilgen-0.1.0-linux-x64.AppImage` or `Sigilgen-0.1.0-linux-x64.deb` |

`SHA256SUMS.txt` lists the checksums. Builds are **unsigned**: Windows shows SmartScreen, macOS needs
the Control-click → Open confirmation, and the AppImage needs `chmod +x`. The full install notes and
verification list are in [docs/releases/desktop-0.1.0.md](../../docs/releases/desktop-0.1.0.md); the
release history is in [CHANGELOG.md](CHANGELOG.md).

## Stack

| Layer     | Choice                                 | Why                                                              |
| --------- | -------------------------------------- | ---------------------------------------------------------------- |
| Runtime   | Electron 45                            | Mature cross-platform webview with consistent Chromium rendering |
| Build     | electron-vite 6 (Vite 8)               | Main/preload/renderer in one dev loop, HMR included              |
| UI        | React 19 + Tailwind 4, from `apps/web` | One interface, two hosts                                         |
| Language  | TypeScript 7, strict                   | Same rules as the rest of the repository                         |
| Packaging | electron-builder 26                    | NSIS and portable on Windows, DMG/ZIP on macOS, AppImage/DEB     |

Tauri was considered and would produce a smaller binary, but it needs a Rust toolchain and Microsoft's
C++ build tools on Windows. Electron keeps the build reproducible with Node alone and gives the studio
the same Chromium on every platform, which matters for a design tool.

## Run it

The desktop package imports the studio's **source**, so install its dependencies too:

```bash
pnpm install                    # repository root (the generator)
pnpm --dir apps/web install     # the studio
pnpm --dir apps/desktop install # the shell
pnpm --dir apps/desktop dev     # HMR: web UI + Electron
```

If GitHub's release downloads are blocked, point Electron's installer at a mirror:

```powershell
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
pnpm --dir apps/desktop install
```

The install script for Electron downloads its binary; if it was skipped (`out/` builds but no window
opens), run `node apps/desktop/node_modules/electron/install.js` once with the same mirror set.

## Build and package

```bash
pnpm --dir apps/desktop run build       # out/main, out/preload, out/renderer
pnpm --dir apps/desktop run start       # run the built app
pnpm --dir apps/desktop run dist        # installer for the current OS
pnpm --dir apps/desktop run dist:win    # NSIS + portable
pnpm --dir apps/desktop run dist:mac    # DMG + ZIP, x64 and arm64
pnpm --dir apps/desktop run dist:linux  # AppImage + DEB
```

Output lands in `release/`. Builds are **unsigned** by default; shipping to users needs an Authenticode
certificate on Windows and Developer ID plus notarization on macOS.

### Releasing

1. Bump `version` in `apps/desktop/package.json`.
2. Add the release to `apps/desktop/CHANGELOG.md` and a notes file under `docs/releases/`.
3. Merge the change to `main`, then tag it `desktop-v<version>` and push the tag.
4. `.github/workflows/desktop.yml` builds Windows, macOS and Linux on the tag and uploads the
   installers as artifacts.
5. Download the artifacts, generate `SHA256SUMS.txt`, and attach both to a GitHub Release whose body is
   the notes file.

The workflow also accepts a manual dispatch and runs the desktop gate on pull requests.

The app icon is generated by Sigilgen itself:

```bash
pnpm build                                  # root, for dist/index.js
pnpm --dir apps/desktop run icons
```

## Window behaviour

The window is not frameless. Windows and macOS keep their native caption controls, which is what
preserves Snap Layouts, double-click-to-maximize, the system menu and screen-reader names. Only the
strip behind them is ours.

| Platform | Title bar                                                      | Controls                        |
| -------- | -------------------------------------------------------------- | ------------------------------- |
| Windows  | `titleBarStyle: hidden` + `titleBarOverlay`, themed at runtime | Native, right                   |
| macOS    | `hiddenInset`, traffic lights at 14/11                         | Native, left                    |
| Linux    | Ordinary window frame                                          | Native, wherever the WM puts it |

- The strip is a drag region; the in-app title island is not.
- Full screen hides the strip entirely.
- Bounds, position and the maximized flag are written to `window-state.json` in the Electron
  `userData` directory. A window saved on a monitor that is no longer connected is centred on the
  primary display; a window smaller than the studio's minimum is clamped.
- Closing quits on Windows/Linux. On macOS the app stays in the dock, as native apps do, and reopens
  from the dock.
- A second launch focuses the existing window instead of opening another one.

## Native integration

| Surface   | Behaviour                                                                          |
| --------- | ---------------------------------------------------------------------------------- |
| Menu      | Localized from the OS locale; Save, Undo/Redo, edit roles, zoom, full screen, help |
| Save      | Native Save dialog, `.svg` filter, suggested name from the brand name              |
| Clipboard | Electron's clipboard, with the web path kept as a fallback                         |
| Links     | `http`/`https` only, opened in the default browser                                 |
| Undo/Redo | Routed through the studio, so a field undo stays a field undo                      |

## Security

The renderer is treated as a hostile page:

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webviewTag: false`
- a preload bridge with named verbs, never `ipcRenderer` or a filesystem path
- every IPC handler checks the sender and validates the payload; SVG writes are capped at 8 MB and
  must start with `<svg`
- external navigation is denied and only http(s) URLs reach `shell.openExternal`
- camera, microphone, location and notification permissions are denied
- the production page carries a CSP; `object-src`, `base-uri` and form submissions are disabled
- single-instance lock, no remote content

## Tests

```bash
pnpm --dir apps/desktop run check   # lint, format, typecheck, tests, build
```

`tests/` covers the parts that are easy to get wrong without a window: restoring geometry across
monitors, sanitizing a suggested file name, the URL allowlist and menu localization. The studio's own
suite covers the desktop bridge and the custom strip in jsdom (`apps/web/tests/desktop.test.tsx`).

## Layout

```
src/
├── main/
│   ├── index.ts          app lifecycle, window creation, security policy
│   ├── ipc.ts            the validated bridge handlers
│   ├── menu.ts           native menu
│   ├── menu-labels.ts    localized labels (pure, testable)
│   ├── validation.ts     file-name and URL checks (pure, testable)
│   └── window-state.ts   geometry restore rules (pure, testable)
├── preload/index.ts      the named bridge exposed to the studio
└── ...
scripts/build-icon.mjs    draws build/icon.png and build/icon.ico with Sigilgen
```

The renderer is `apps/web` itself: `electron.vite.config.ts` points Vite's root there and bundles
`apps/web/index.html`. A change to the studio is a change to the desktop app with no copy to keep in
step.
